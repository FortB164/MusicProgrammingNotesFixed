## 1. Definitions

**Music Information Retrieval (MIR)**
An interdisciplinary field concerned with extracting, organising, searching, and evaluating information from music-related data.

**MIR Inputs:** Audio recordings, MIDI/MusicXML/ABC notation, lyrics and metadata, musical scores and annotations, user interaction data.

**MIR Outputs:** Detected musical events and beats, estimated pitch or melody, audio features, labels and similarity scores, search results or recommendations.

**This session focuses on:** audio-based low-level analysis — amplitude, onsets, tempo, and monophonic pitch.

**Onset**
The estimated beginning of a musically significant sound event.
- Examples: a piano key being struck, a drum hit, the beginning of a sung note, the start of a guitar note, the beginning of a synthesised event.

**In symbolic data:** MIDI, MusicXML, ABC notation, or Python events may provide the onset directly.

**In audio:** the onset is not explicitly stored. The system must estimate it from evidence such as:
- Rapid amplitude increase
- Spectral change
- Phase change
- Change in pitch or timbre

**Important:** An onset is not necessarily a beat, the maximum-amplitude position, the first non-zero sample, or the beginning of a musical measure. Legato notes, bowed instruments, reverberation, and gradual attacks can make onset boundaries ambiguous.

**Beat**
An estimated regular pulse position.
- Output: 0.50 s, 1.00 s, 1.50 s, ...
- A beat may contain one onset, several onsets, or no onset.

**Tempo**
The rate of the musical pulse, normally expressed in beats per minute (BPM).
- Output: 120 BPM
- Tempo may be one global value, a local value that changes over time, or ambiguous between metrical levels.
- **The algorithm in this session estimates global tempo. It does not perform complete beat tracking.**

**Amplitude Envelope**
A frame-wise summary of how signal magnitude changes over time. The peak envelope tracks the largest absolute sample in each frame.

**Root Mean Square (RMS) Amplitude**
Summarises the average signal power within a frame. RMS reduces the effect of outliers in the amplitude envelope algorithm.

**Frame Length**
The number of audio samples analysed together.
- A longer frame normally provides: better frequency resolution, poorer time localisation, increased computation.

**Hop Length**
The number of audio samples by which the analysis frame moves forward when creating the next frame.
- A shorter hop length provides: more frequent feature values, better sampling of temporal changes, more frame overlap, increased computation.

**Window Function**
Gradually reduces the samples near the frame boundaries to minimise abrupt discontinuities and reduce spectral leakage when calculating the frequency spectrum.

**Spectrum**
Shows the frequency content of one selected audio frame or time region.
- Can reveal: fundamental frequency, harmonics, spectral shape, brightness, noise components.
- Describes frequency content at one selected moment or short region.

**Spectrogram**
Shows how the frequency content changes over time.
- Can reveal: note attacks, sustained harmonics, pitch movement, changes in timbre, silence and active regions, frequency changes over time.
- A sequence of spectra calculated from overlapping audio frames.

**Pitch Detection**
Estimates the fundamental frequency (\(f_0\)) of a voiced sound.
- A3 → approx. 220 Hz
- A4 → approx. 440 Hz
- A5 → approx. 880 Hz
- A spectrum may contain peaks at \(f_0, 2f_0, 3f_0, \ldots\)
- The largest spectral peak is not always the fundamental.

**Digital music libraries and sound archives:**
- Traditional catalogue search uses metadata: title, composer, performer, date, genre.
- Users may want to search for information inside the audio: similar melodies or rhythms, instruments or voices, tempo/pitch/key/chords, repeated sections, duplicate recordings, acoustically similar material.

- **Legacy collections** may contain missing/inconsistent metadata, unlabelled recordings, noisy/degraded audio, duplicate versions, collections too large for complete manual annotation. MIR can generate provisional descriptors, but expert verification remains important.

**Legal and copyright applications:**
- Rights holders may need to determine: Does a new recording contain an exact or modified sample? Has a melody/rhythm/lyric/passage been copied? Has the original material been pitch-shifted, time-stretched, filtered, rearranged, or repeated? Where does the potentially matching passage occur?
- MIR can extract audio fingerprints and musical features, compare against large databases, and report relevant passages, timestamps, and estimated transformations.
- **A high similarity score is evidence of a possible match, not automatic proof of copyright infringement.**

**Recording studio applications:**
- Follow the performer's position in a digital score.
- Align recordings with MIDI or MusicXML.
- Compare timing, pitch, and tempo across different takes.
- Add timestamps and section labels automatically.
- Search and navigate large multitrack recording sessions.
- Support editing, synchronisation, and take management.

### MIR Pipeline
```
1. Load and validate audio
2. Frame and window the signal
3. Compute a representation
4. Extract evidence or features
5. Make estimates
6. Evaluate against reference data
7. Compare with annotations using: accuracy, precision/recall, F-measure, etc.
```

### Time-Domain Representation
**Strengths:**
- Computationally inexpensive
- Easy to calculate and interpret
- Operates directly on audio samples
- Suitable for real-time processing

**Applications:**
- Amplitude analysis
- Silence detection
- Attack and decay analysis
- Clipping detection
- Onset detection
- Temporal segmentation
- Dynamic-shape comparison

**Limitations:**
- Sensitive to recording level
- Sensitive to background noise
- Does not describe pitch
- Does not describe harmonic structure
- Soft or legato events may create weak amplitude changes
- Amplitude is not identical to perceived loudness

### Frequency-Domain Representation
**Main properties:**
- Shows how energy is distributed across frequencies.
- Reveals harmonics and spectral shape.
- Usually calculated for short frames using the Fourier transform.
- Does not directly preserve the detailed time position of events.

**Applications:**
- Pitch detection
- Harmonic analysis
- Timbre analysis
- Spectral filtering
- Bandwidth measurement
- Instrument analysis
- Frequency-domain onset detection

**Key idea:** Neither domain is universally better. The appropriate representation depends on the MIR task.

### Framing and Windowing
Music changes over time, so audio analysis is usually performed on short, overlapping segments called frames.

**Framing and windowing process:**
```
Audio signal S(t)
→ Frame 1 (e.g. samples 0–255)
→ Window function W(n) (e.g. Hanning)
→ Windowed frame X_m[n] = S(n) · W(n)
→ Next frame starts at hop length H (e.g. 128)
```

**Frame length (N):** duration of each audio segment
**Hop length (H):** step size between frame starts
**Overlap:** amount that frames share (N − H)

**Example:**
- sample_rate = 22050
- frame_length = 2048
- hop_length = 512

**Frame duration:**
\[
\frac{2048}{22050} \approx 0.0929 \text{ seconds}
\]
**Hop duration:**
\[
\frac{512}{22050} \approx 0.0232 \text{ seconds}
\]
**Feature rate:**
\[
\frac{22050}{512} \approx 43.07 \text{ feature values per second}
\]

### Amplitude Envelope
The peak envelope tracks the largest absolute sample in each frame.

**Formula:**
\[
E[m] = \max_{n \in \text{Frame}[m]} |x[n]|
\]
- \(x[n]\) = audio sample
- \(E[m]\) = peak-amplitude value for frame \(m\)

**Applications:**
- Detecting sharp attacks
- Finding loud events
- Identifying clipped or high-amplitude regions
- Providing evidence for onset detection
- Measuring amplitude changes over time

**Limitations:**
- Sensitive to isolated noise spikes
- Depends on frame length
- May react strongly to one extreme sample
- Usually requires smoothing before change detection

### Root Mean Square (RMS) Amplitude
RMS reduces the effect of outliers in the amplitude envelope algorithm.

**Formula:**
\[
\text{RMS}[m] = \sqrt{\frac{1}{N} \sum_{n=0}^{N-1} x_m[n]^2}
\]
- **Squaring:** prevents positive and negative samples from cancelling each other.
- **Averaging:** describes the overall energy of the frame.
- **Square root:** returns the result to the original amplitude scale.

**Properties:**
- Smoother than peak amplitude
- Less sensitive to isolated spikes (outliers)
- Depends on frame length
- Describes signal energy, not frequency content
- Does not equal perceived loudness

**Applications:**
- Silence detection
- Audio-activity detection
- Dynamic analysis
- Onset detection
- Segmenting recordings by energy

### Onset Detection Algorithm
**General idea:** The algorithm divides the audio into overlapping frames, calculates and smooths a peak-amplitude envelope, and measures the positive increase between consecutive envelope values. Significant local peaks that exceed an adaptive threshold are treated as onset candidates; nearby candidates are filtered so that only the stronger one remains, and the selected frame centres are converted into onset times in seconds.

**Analysis settings (example):**
- Sample rate = 1,000 samples/second
- Frame length = 100 samples
- Hop length = 50 samples
- Smoothing length = 3 frames
- Threshold radius = 2 frames
- Sensitivity = 3
- Minimum onset interval = 0.20 seconds

**Frame-centre offset:** frame length / 2 = 50 samples

**Steps:**
1. **Divide the audio into overlapping frames** — frame 0: samples 0–99; frame 1: samples 50–149; frame 2: samples 100–199; frame 3: samples 150–249; ...
2. **Calculate the peak amplitude of each frame** — e.g. `[0.05, 0.06, 0.08, 0.60, 0.50, 0.12, 0.10, 0.70, 0.55, 0.12]`
3. **Smooth the amplitude envelope** — centred three-frame moving average:
   \[
   E_s[m] = \frac{E[m-1] + E[m] + E[m+1]}{3}
   \]
   Example: \(E_s[2] = (0.06 + 0.08 + 0.60)/3 = 0.247\); \(E_s[7] = (0.10 + 0.70 + 0.55)/3 = 0.450\)
   Smoothed envelope ≈ `[0.037, 0.063, 0.247, 0.393, 0.407, 0.240, 0.307, 0.450, 0.457, 0.223]`
4. **Calculate positive amplitude changes:**
   \[
   D[m] = E_s[m] - E_s[m-1]
   \]
   \[
   O[m] = \max(0, D[m])
   \]
   Example: \(D[2] = 0.247 - 0.063 = 0.184\); \(D[5] = 0.240 - 0.407 = -0.167 \rightarrow O[5] = 0\)
   Positive onset-strength values ≈ `[0.000, 0.026, 0.184, 0.146, 0.014, 0.000, 0.067, 0.143, 0.007, 0.000]`
5. **Normalise the values** — divide every onset-strength value by the largest value (0.184):
   `[0.000, 0.141, 1.000, 0.793, 0.076, 0.000, 0.364, 0.777, 0.038, 0.000]`
6. **Calculate the adaptive threshold:**
   \[
   T[m] = \text{local median} + 3(\text{local MAD} + 0.01)
   \]
   - 3 controls sensitivity (threshold three local MAD units above the median).
   - 0.01 provides a small threshold floor so silence or zero local variation does not produce a zero threshold.
   - Both values are adjustable hyperparameters, not universal constants.
   - Example around frame 2: local neighbourhood `[0.000, 0.141, 1.000, 0.793, 0.076]`, local median = 0.141, absolute deviations ≈ `[0.141, 0.000, 0.859, 0.652, 0.065]`, MAD = 0.141, threshold \(T[2] = 0.141 + 3(0.141 + 0.01) = 0.594\).
   - Adaptive threshold array ≈ `[0.594, 1.687, 0.594, 0.594, 1.486, 1.486, 0.334, 0.182, 0.777, 0.182]`.
7. **Find candidate onsets** — must be a local maximum AND above the adaptive threshold.
   - Frame 2: previous = 0.141, current = 1.000, next = 0.793, threshold = 0.594 → candidate.
   - Frame 7: previous = 0.364, current = 0.777, next = 0.038, threshold = 0.182 → candidate.
   - Candidate frames = `[2, 7]`.
8. **Remove candidates that are too close:**
   \[
   \text{minimum frames} = \text{round}\left(\frac{0.20 \times 1000}{50}\right) = 4
   \]
   Distance between candidates = 7 − 2 = 5 frames ≥ 4 → sufficiently separated. Selected frames = `[2, 7]`.
   If two candidates had been fewer than four frames apart, only the candidate with the greater onset-strength value would have been retained.
9. **Convert the frames into onset times** using the centre of each frame:
   \[
   t = \frac{\text{frame index} \times \text{hop length} + \text{frame length}/2}{\text{sample rate}}
   \]
   - Frame 2: \(t_1 = (2 \times 50 + 50)/1000 = 0.150\) seconds
   - Frame 7: \(t_2 = (7 \times 50 + 50)/1000 = 0.400\) seconds

**Final result:** Detected onset frames = `[2, 7]`, onset times = `[0.150 s, 0.400 s]`.

**Algorithm summary:**
1. Divide audio into overlapping frames.
2. For each frame: amplitude ← maximum absolute sample.
3. Smooth the amplitude envelope using a moving average.
4. Calculate positive amplitude changes:
   `change[i] = envelope[i] - envelope[i-1]`, `onsetStrength[i] = MAX[0, change[i]]`.
5. Normalise the envelope and onset-strength values.
6. For each frame: calculate local median, local MAD, threshold.
7. Find candidate onsets that are local peaks AND above threshold.
8. If two candidates are too close: keep the stronger candidate.
9. Convert each selected frame to time using the centre of the frame.

**Common problems:**
| Problem | Possible causes |
|---|---|
| **False positives** | Background noise, reverberation, tremolo, repeated peaks from one event, sudden level changes unrelated to a new note |
| **Missed onsets** | Soft attacks, legato transitions, bowed instruments, overlapping notes, gradual amplitude increases |
| **Timing offset** | Smoothing and frame-based processing may cause the detected onset to occur slightly sooner or later than the real onset |
| **Evaluation** | An estimate is considered correct when it lies within a tolerance window (e.g. reference 1.000 s, estimate 1.031 s, tolerance ±0.050 s → match) |

### Tempo Estimation
**Key distinction:**
- **Onset:** beginning of a detected musical event. Output: 0.25 s, 0.74 s, 1.23 s, ... Events do not need to occur on beats.
- **Beat:** an estimated regular pulse position. Output: 0.50 s, 1.00 s, 1.50 s, ... A beat may contain one onset, several onsets, or no onset.
- **Tempo:** rate of the musical pulse, normally in BPM. Output: 120 BPM.

**Algorithm:** Estimates tempo by finding regular repetition in the onset-strength envelope.

1. **Compute the onset-strength envelope** — use the amplitude-change onset-strength function.
2. **Centre the onset-strength function:**
   \[
   O_c[m] = \text{onset\_strength}[m] - \text{np.mean(onset\_strength)}
   \]
   Removes the constant positive baseline and makes periodic variation more prominent.
3. **Calculate autocorrelation:**
   \[
   R[\ell] = \sum_{m=0}^{N-1-\ell} O_c[m] O_c[m+\ell]
   \]
   - \(O_c[m]\) = mean-centred onset strength at frame \(m\)
   - \(\ell\) = lag, \(0 \le \ell \le N-1\)
   - \(N\) = number of onset-strength values
   - A large sum indicates that the rhythmic pattern repeats at that delay.
4. **Restrict the lag range** — only examine lags corresponding to a realistic tempo range, such as 50 BPM to 200 BPM.
5. **Select the strongest lag** — choose the lag with the highest autocorrelation value within the permitted range.
6. **Convert the lag to BPM** — use the onset-envelope sampling rate to convert the selected lag into tempo. Regularly spaced onset peaks produce strong autocorrelation values at the beat period and its multiples.

**Envelope sampling rate:**
\[
r = \frac{\text{audio sample rate}}{\text{hop length}}
\]
For sample rate = 22,050 Hz and hop length = 256 samples:
\[
r = \frac{22050}{256} \approx 86.13 \text{ values per second}
\]

**Convert lag to BPM:** If \(L\) is the lag (in onset-strength frames) at the strongest meaningful autocorrelation peak within the permitted range:
\[
\text{beat period in seconds} = \frac{L}{r}
\]
\[
\text{BPM} = \frac{60}{L/r} = \frac{60r}{L}
\]

**Convert BPM range to lag range:**
\[
L_{\min} = \frac{60r}{\text{maximum BPM}}
\]
\[
L_{\max} = \frac{60r}{\text{minimum BPM}}
\]

**Example at 120 BPM:** beat period = 60/120 = 0.5 s. At onset-envelope rate ≈ 86.13 frames/second: \(L = 0.5 \times 86.13 \approx 43.07\) frames.

**Half-tempo and double-tempo ambiguity are normal** because periodic patterns produce peaks at related lags.

**Why return multiple candidates?** Related autocorrelation lags may represent half tempo, double tempo, or another metrical interpretation.

**Common failure modes:**
- Syncopation
- Weak attacks
- Irregular rhythms
- Tempo changes
- Very short recordings
- Repeated subdivisions
- Strong off-beat events
- Half-tempo ambiguity (e.g. 60 BPM vs 120 BPM vs 240 BPM)
- Double-tempo ambiguity

**More robust systems may combine:** spectral onset features, multiple tempo candidates, tempo priors, dynamic programming, beat-sequence tracking, local tempo estimation.

### Spectrum vs Spectrogram
| Spectrum | Spectrogram |
|---|---|
| Analyses one frame or region | Analyses a sequence of frames |
| Shows frequency and magnitude | Shows time, frequency, and magnitude |
| Useful for inspecting harmonics | Useful for observing musical development |
| Does not show temporal evolution | Shows how spectral content changes |

### Pitch Detection with Librosa (pYIN)
librosa provides `librosa.pyin()`, an implementation of probabilistic YIN. It first generates fundamental-frequency candidates and probabilities using YIN, then uses Viterbi decoding to estimate the most likely pitch sequence and voiced/unvoiced states.

**Outputs:**
- `f0`: estimated fundamental frequency for each frame, with `NaN` normally representing unvoiced frames
- `voiced_flag`: True or False indicating whether each frame is voiced
- `voiced_probability`: confidence value between 0 and 1 for the voiced decision
- `fmin` and `fmax`: restrict the expected pitch range

**Limitations:** `librosa.pyin()` is best suited to monophonic fundamental-frequency estimation. It does not perform complete polyphonic transcription. Possible difficulties include: polyphonic audio, noisy recordings, weak or missing fundamentals, rapid pitch changes, strong reverberation, transients, pitch outside the selected `fmin`/`fmax` range, octave errors.

The selected pitch range should match the expected source. A narrower, realistic range can improve results.

## 3. Code

### 3.1 Amplitude Envelope

```python
def amplitude_envelope(audio, frame_length, hop_length):
    frames = frame_signal(audio, frame_length, hop_length)
    return np.max(np.abs(frames), axis=1)
```

The audio is divided into overlapping frames. The absolute value removes the distinction between positive and negative sample amplitudes, and the maximum value is selected across each frame using `axis=1`. The result is one peak-amplitude value per frame.

**Note:** The framed signal is a 2D array — each row is one audio frame, each column is one sample position within that frame. Using `axis=1` calculates the maximum across all samples in each row.

### 3.2 RMS Amplitude

```python
def rms_energy(audio, frame_length, hop_length):
    frames = frame_signal(audio, frame_length, hop_length)
    return np.sqrt(np.mean(frames * frames, axis=1))
```

The audio is divided into overlapping frames. Each sample is squared, the squared values are averaged across each frame using `axis=1`, and the square root is taken. The result is one RMS value per frame.

### 3.3 Autocorrelation Tempo (from Scratch)

```python
O_c = onset_strength - np.mean(onset_strength)
autocorrelation = np.correlate(O_c, O_c, mode="full")[O_c.size-1:]

# Normalisation
if autocorrelation[0] > 0:
    autocorrelation = autocorrelation / autocorrelation[0]

envelope_rate = sample_rate / hop_length
min_lag = int(60 * envelope_rate / maximum_bpm)
max_lag = int(60 * envelope_rate / minimum_bpm)

search = autocorrelation[min_lag : max_lag + 1]
best_lag = np.argmax(search) + min_lag
bpm = 60 * envelope_rate / best_lag
```

**Input:** onset-strength envelope, sample rate, hop length, minimum BPM, maximum BPM.
**Output:** one global BPM estimate, ranked alternative tempo candidates (see full Python code).

### 3.4 Generating a Spectrum with Librosa

Full code is in `spectrum_spectrogram.py` on Moodle.

```python
# Select the time position of the frame.
frame_start_seconds = 0.5
start_sample = int(frame_start_seconds * sample_rate)
frame = audio[start_sample : start_sample + FRAME_LENGTH]

# Pad the frame if it reaches beyond the end of the audio.
if len(frame) < FRAME_LENGTH:
    frame = np.pad(frame, (0, FRAME_LENGTH - len(frame)))

# Apply a Hann window to reduce spectral leakage.
windowed_frame = frame * np.hanning(FRAME_LENGTH)

# Calculate the real-valued FFT magnitude.
spectrum = np.abs(np.fft.rfft(windowed_frame))

# Calculate the frequency represented by each FFT bin.
frequencies = np.fft.rfftfreq(FRAME_LENGTH, d=1.0 / sample_rate)
```
