## 1. Definitions

**MusicXML**
An open XML-based format for representing, exchanging, and archiving digital sheet music.

- Represents score structure and notation details.
- Can be read and written by many notation tools.
- Can be parsed with standard XML tools.

**Key point:** MusicXML is strongest when the notation itself matters.

**Why MusicXML is used:**
- **Detailed score information** — notes, rests, measures, parts, voices, lyrics, articulations, layout.
- **Application exchange** — move scores between notation editors, DAWs, educational tools, and analysis software.
- **Standard XML tooling** — parse, search, validate, transform, and archive using well-known XML workflows.
- **Compressed and uncompressed files** — `.musicxml` for readable XML; `.mxl` for ZIP-compressed packages.

**XML (eXtensible Markup Language)**
Represents hierarchical data using elements and attributes. Elements can contain text, attributes, or nested elements.

**Core XML rules:**
- Every well-formed document has one root element.
- Opening and closing tags must be correctly nested.
- A schema defines which elements and values are allowed for a particular format.

**Key distinction:**
- **XML** gives the syntax (general hierarchical data, elements, attributes, text, namespaces, standard parsing tools, validation).
- **MusicXML** gives the musical vocabulary (predefined music-specific tags, rules for valid score structure, elements for notation/performance/layout, interoperability between score applications).

**Two broad types of information in MusicXML:**
1. **Metadata** — title, creator/composer, part names, software or encoding information.
2. **Musical content** — measures, attributes, notes and rests, chords and voices, barlines and layout.

**MusicXML hierarchy (example):**
```
score-partwise
├── work
│   └── work-title
├── identification
│   └── creator
├── part-list
│   └── score-part: P1
└── part: P1
    ├── measure 1
    │   ├── attributes
    │   └── C4 whole note
    └── measure 2
        ├── C5 quarter note
        ├── G4 quarter note
        ├── half rest
        └── final barline
```

**Divisions**
Specifies how many MusicXML duration units make up one quarter-note beat.
```
duration in quarter-note beats = MusicXML duration ÷ divisions
```
Example: divisions = 1, duration = 4 → 4 quarter-note beats.

**Attributes**
The `<attributes>` element establishes the notation context for a measure:
- `divisions` — duration resolution
- `key/fifths` — key signature (0 = no sharps or flats)
- `time` — time signature (beats / beat-type)
- `clef` — clef (sign + line)

**Key idea:** A measure inherits attributes from the previous measure unless something changes.

**Rest**
A MusicXML rest has duration but no pitch. Represented as `<rest/>`, equivalent to `<rest></rest>`.

**Important:** A rest still occupies time on the musical timeline; it simply produces no pitch.

**Chord in MusicXML**
Following notes use `<chord/>` to share the previous note's onset.

**Key idea:** `<chord/>` does not mean "make a chord object"; it means the following note shares the previous note's onset.

**Final Barline**
Notation structure that does not consume musical time.
- `<barline location="right">` + `<bar-style>light-heavy</bar-style>` = thin line followed by thick line.
- Often marks the end of a work or major section.
- **Notation vs timing:** note duration affects playback time; barline style affects score appearance and structure. The barline itself does not advance the musical clock.

**Compressed .mxl Files**
| Suffix | Meaning |
|---|---|
| `.musicxml` | Uncompressed XML |
| `.mxl` | ZIP-compressed MusicXML package |
| `.xml` | Older generic suffix sometimes encountered |

## 2. Explanations

### What MusicXML Is
A structured, exchangeable representation of digital sheet music. It stores musical notation as structured data that software can exchange and process.

```
Notation software → MusicXML file → Another application
(score editor)       (<score-partwise>)  (import / render / analyse)
```

More than 270 applications claim some level of MusicXML support, although support for individual features can vary.

### XML vs MusicXML
- **XML provides:** general syntax for hierarchical data, elements, attributes, text, and namespaces, standard parsing tools, validation mechanisms.
- **MusicXML provides:** a music-specific vocabulary (predefined tags), rules for valid score structure, elements for notation/performance/layout, interoperability between score applications.

MusicXML parsing is just XML parsing plus music-specific meaning.

### Part Declaration and Part Content
MusicXML separates a part's identity from the music stored in it.

```xml
<part-list>
  <score-part id="P1">
    <part-name>Flute</part-name>
  </score-part>
</part-list>

<part id="P1">
  ... (contains the measures) ...
</part>
```

- **Declaration:** P1 → Flute
- **Content:** `<part id="P1">` contains the measures
- The `<part>` element uses the same `id`, so Python can recover the name.

### Measure and Attributes
The `<attributes>` element establishes the notation context.

Example context in measure 1:
- `divisions = 1` → 1 MusicXML duration unit = 1 quarter-note unit
- `fifths = 0` → no sharps or flats in the key signature (C major / A minor)
- `4/4` → 4 quarter-note beats per measure
- `G on line 2` → treble clef

**Key idea:** Measure 2 inherits these attributes unless something changes.

### How Divisions Works
Divisions specifies how many MusicXML duration units make up one quarter-note beat.

| MusicXML duration | divisions | Duration in quarter-note beats |
|---|---|---|
| 4 | 1 | 4 ÷ 1 = 4 beats |
| 1 | 1 | 1 ÷ 1 = 1 beat |
| 2 | 1 | 2 ÷ 1 = 2 beats |

If divisions = 2: 1 duration unit = 1/2 quarter-note beat.

**Validate the denominator:** a zero or negative divisions value would make the conversion invalid.

### Measure 2 as Sequence of Events
Measure 2 contains: C5 quarter note → G4 quarter note → half rest.
Durations: 1 + 1 + 2 = 4 quarter-note beats.

**Local vs global onset:**
- Measure 1 lasts 4 beats, so measure 2 begins at global onset 4.
- Local onset 0 → Global onset 4 → C5
- Local onset 1 → Global onset 5 → G4
- Local onset 2 → Global onset 6 → REST

### Chords in MusicXML
Following notes use `<chord/>` to share the previous note's onset.

**Without `<chord/>`:** C4 and E4 have different onsets (sequential).
**With `<chord/>`:** C4 and E4 have the same onset (simultaneous).

### MusicXML vs ABC vs MIDI
| Format | Best for | Main limitation |
|---|---|---|
| MusicXML | Rich score notation, exchange, archiving | Verbose; feature support can vary |
| ABC | Plain-text melodies and compact notation | Less suitable for complex engraved scores |
| MIDI | Performance messages, timing, playback | Does not encode notation details such as spelling or beams |
| Audio | The resulting sound waveform | Hard to recover notation or symbolic events |

**Example:** MIDI note 66 might be F# or Gb depending on context; MusicXML and ABC notation can represent the spelling.

**Takeaway:** MusicXML is about the score; MIDI is about performance instructions; audio is the sound itself.

### Important Limitation of the Simplified Parser
The simplified parser works for the supplied example, but real MusicXML can be much richer.

**The example assumes:**
- One part
- One voice
- No chords
- No altered pitches
- No ties
- Sequential events
- One unchanged divisions value
- No backup or forward elements

**A production parser must handle:**
- Polyphony and multiple voices
- Multiple parts and changing attributes
- Chords, ties, tuplets, and grace notes
- Layout and engraving details
- Backup and forward elements

**This is a good reason to use a library such as music21 or Partitura for realistic files.**

### Processing MusicXML with music21
music21 parses MusicXML into higher-level music objects.

**What music21 gives you:**
- `converter.parse(...)` — reads the MusicXML file and creates a Score object.
- `score.metadata` — provides metadata such as title and composer.
- `score.parts` — iterates through the instrumental parts.
- `Measure` — lets you inspect the score measure by measure.
- `notesAndRest` — returns musical events, including rests.
- `offset` / `quarterLength` — gives timing and duration.

**Why use it?** Real MusicXML may contain multiple voices, chords, ties, changes of time signature, and more.

### Useful Python Libraries for MusicXML
**music21** — toolkit for computer-aided musical analysis and computational musicology. Good for symbolic music objects, music-theory analysis, parsing, conversion, transposition, chord and key analysis. `converter.parse()` can read MusicXML among other supported formats.

**Partitura** — Python package for symbolic musical information. Supports loading and exporting MusicXML and MIDI. Useful for structured note arrays, score-performance alignment, MIR, and computational-music applications.

### A Practical MusicXML Application
MusicXML enables structured search and analysis of symbolic scores.

Example: **MusicSQL** — a system for conducting complex searches of symbolic polyphonic music databases. Searches are constructed relationally and can be multidimensional, searching for patterns in multiple voices and other musical parameters. Database can import and export MusicXML files. This illustrates why structured score data matters: it can be queried, transformed, and analysed.

## 3. Code

### 3.1 Basic XML Parsing with ElementTree

```python
import xml.etree.ElementTree as ET

root = ET.fromstring(xml_text)

step = root.findtext("pitch/step")
octave = root.findtext("pitch/octave")
duration = root.findtext("duration")

print(step, octave, duration)
```

**How it works:**
1. `<note>` is the root element — everything in the snippet belongs to one note.
2. Parse the XML string — `ET.fromstring(...)` converts text into an XML element tree.
3. `<pitch>` groups pitch information — `<step>` stores C and `<octave>` stores 4.
4. Navigate with paths — `findtext(...)` follows child elements and returns their text.

### 3.2 Reading Title and Composer

```python
import xml.etree.ElementTree as ET

tree = ET.parse("simple_score.musicxml")
root = tree.getroot()

title = root.findtext("work/work-title")
composer = root.findtext(
    "identification/creator[@type='composer']"
)

print("Title:", title)
print("Composer:", composer)
```

**Expected output:**
```
Title: The Name of the Tune
Composer: Composer / arranger
```

**Idea:** parse the XML → get the root → navigate to child elements → extract metadata text.

### 3.3 Part Declaration and Content Mapping

```python
part_names = {}

for score_part in root.findall(
    "part-list/score-part"
):
    part_id = score_part.get("id")
    part_name = score_part.findtext("part-name")
    part_names[part_id] = part_name

for part in root.findall("part"):
    part_id = part.get("id")
    print(part_id, part_names.get(part_id))
```

**Expected output:** `P1 Flute`

The declaration section tells us what P1, P2, ... mean. The `<part>` element uses the same `id`, so Python can recover the name.

### 3.4 Reading Key, Time Signature, and Clef

```python
attributes = root.find(
    "./measure[@number='1']/attributes"
)

fifths = int(attributes.findtext("key/fifths"))
beats = int(attributes.findtext("time/beats"))
beat_type = int(attributes.findtext("time/beat-type"))
clef_sign = attributes.findtext("clef/sign")
clef_line = int(attributes.findtext("clef/line"))

print("Fifths:", fifths)
print("Time signature:", f"{beats}/{beat_type}")
print("Clef:", f"{clef_sign} on line {clef_line}")
```

**Expected output:**
```
Fifths: 0
Time signature: 4/4
Clef: G on line 2
```

**Meaning:**
- `0 fifths` → C major / A minor key signature
- `4/4` → 4 beats, quarter-note beat unit
- `G on line 2` → treble clef

**Key points:**
- Find the `<attributes>` element — the XPath locates measure 1 and then its notation context.
- Convert numeric text to int — `findtext(...)` returns strings, so numeric values are converted explicitly.

### 3.5 Duration Conversion

```python
def duration_to_quarter_beats(
    duration_value, divisions
):
    if divisions <= 0:
        raise ValueError("divisions must be positive.")
    return duration_value / divisions

print(duration_to_quarter_beats(4, divisions))  # 4.0
print(duration_to_quarter_beats(1, divisions))  # 1.0
print(duration_to_quarter_beats(2, divisions))  # 2.0
```

**Validate the denominator:** a zero or negative divisions value would make the conversion invalid.

### 3.6 Pitch Name from XML Note

```python
def pitch_name_from_xml(xml_note):
    if xml_note.find("rest") is not None:
        return "REST"
    step = xml_note.findtext("pitch/step")
    octave = xml_note.findtext("pitch/octave")
    alter = int(
        xml_note.findtext("pitch/alter", "0")
    )
    accidentals = {
        -2: "bb",
        -1: "b",
        0: "",
        1: "#",
        2: "##"
    }
    return f"{step}{accidentals[alter]}{octave}"
```

**Meaning:**
- No `<alter>` is needed because C is unaltered.
- C#4: `<alter>1</alter>`
- Cb4: `<alter>-1</alter>`

### 3.7 Getting Divisions from Root

```python
import xml.etree.ElementTree as ET

def get_divisions(root):
    divisions_text = root.findtext(
        "./attributes/divisions"
    )
    return int(divisions_text)
```

Read divisions once — it defines the scale for numeric `<duration>` values.

### 3.8 MusicXML to Events (Simplified Parser)

```python
def musicxml_to_events(filename):
    tree = ET.parse(filename)
    root = tree.getroot()
    divisions = get_divisions(root)
    events = []
    current_onset = 0.0

    for measure in root.findall(
        ".//part/measure"
    ):
        for xml_note in measure.findall("note"):
            duration_units = int(
                xml_note.findtext("duration")
            )
            duration_beats = (
                duration_units / divisions
            )
            pitch_name = pitch_name_from_xml(
                xml_note
            )
            events.append({
                "pitch": pitch_name,
                "onset_beats": current_onset,
                "duration_beats": duration_beats
            })
            current_onset += duration_beats

    return events
```

**Important idea:** Sequential events start after the previous event's duration.

### 3.9 Processing MusicXML with music21

```python
from music21 import converter

score = converter.parse(
    "simple_score.musicxml"
)

score.show("text")

# Extract metadata
print("Title:", score.metadata.title)
print("Composer:", score.metadata.composer)

# Inspect parts and measures
for part in score.parts:
    print("Part:", part.partName)
    for measure in part.getElementsByClass(
        "Measure"
    ):
        print("Measure", measure.number)
        for item in measure.notesAndRest:
            name = item.name if item.isNote else "REST"
            print(
                name,
                item.offset,
                item.quarterLength
            )
```

**What music21 gives you:**
- `converter.parse(...)` — reads the MusicXML file and creates a Score object.
- `score.metadata` — provides metadata such as title and composer.
- `score.parts` — iterates through the instrumental parts.
- `Measure` — lets you inspect the score measure by measure.
- `notesAndRest` — returns musical events, including rests.
- `offset` / `quarterLength` — gives timing and duration.
