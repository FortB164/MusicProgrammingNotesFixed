## 1. Definitions

**MIDI (Musical Instrument Digital Interface)**
A family of technical standards that allows musical instruments, controllers, computers, and software to exchange digital musical messages.

- Represents **actions**, not recorded sound.
- Supports real-time communication between devices and software.
- Can be stored in Standard MIDI Files.

**MIDI vs Audio**
| MIDI | Digital Audio |
|---|---|
| Contains instructions | Contains samples |
| Start/stop a note | Represents changes in signal amplitude |
| Identify a note number | Played directly through an audio system |
| Specify velocity | Depends on sample rate and sample format |
| Select a channel or program | Contains the resulting sound waveform |
| Change controllers (volume, pan, sustain) | — |

**Key idea:** MIDI tells a system **what** to play, **when** to play it, and **how** to play it. MIDI does not sound by itself; a sound generator turns MIDI instructions into audio.

**Live MIDI**
Messages are transmitted as a performance happens.
- Key pressed → note-on
- Wheel moved → pitch bend
- Pedal pressed → control change
- Key released → note-off

**Standard MIDI File (SMF)**
Messages and timestamps are stored for later processing or playback. Timing is encoded rather than performed live. Can be edited, replayed, and shared.

**MIDI Message**
Instructs receiving devices or software to perform or modify musical actions: what note to play, how loud, what instrument, how performance controls change.

**Note Number**
MIDI assigns each pitch an integer from **0 to 127**.

**Velocity**
A performance-control value (0–127). A synthesiser may map it to amplitude, timbre, sample selection, or other parameters. **Velocity is not loudness** — the exact audible result depends on the synthesiser.

**MIDI Channels**
Allow multiple logical performance streams to share one connection.
- Channel 1 → piano
- Channel 2 → bass
- Channel 10 → percussion (General MIDI convention)

**Control-Change Messages**
Controllers often use 0–127 and can be mapped to useful synthesis parameters (e.g. filter cutoff).

**Standard MIDI File — Usually Stores**
- Tracks
- MIDI messages
- Relative event timing
- Tempo and meter metadata
- Track names and other meta-events

**Standard MIDI File — Usually Does NOT Store**
- Recorded audio
- Instrument samples
- Guaranteed timbre
- A complete engraved score

**Delta Time**
In MIDI files, message time is usually **delta time**: the time since the previous message in that track.
```
delta_time = event["absolute_time"] - previous_time
```
Delta time makes MIDI files compact and efficient.

**Ticks Per Beat**
Timing resolution (ticks per quarter note). Example: 480 ticks per beat.

**Tempo (MIDI)**
`bpm2tempo()` converts BPM to MIDI tempo units (microseconds per beat), used in a `set_tempo` meta message.

## 2. Explanations

### What MIDI Is
MIDI represents musical events as digital instructions. A MIDI message can represent:
- `note_on` — starts a note
- `note_off` — ends a note
- A higher-level musical event — pitch, onset, duration, dynamic, articulation

### MIDI Devices and Technology
**Which devices support MIDI:**
- **Controllers** — keyboards, pad controllers, drum controllers, control surfaces
- **Sound generators** — hardware synthesizers, drum machines, samplers
- **Computers** — DAWs, virtual instruments, music applications
- **Mobile devices** — music apps and controller software
- **Interactive systems** — installations, games, lighting, show control
- **Virtual ports** — software-to-software MIDI connections on one computer

**Three aspects of MIDI technology:**
1. **Messages and semantics** — what musical or control action is represented? (note on/off, control change, program change, pitch bend, system and real-time messages)
2. **Transports and connections** — how are messages carried between systems? (cables, USB, Bluetooth, network, virtual ports and routing, one-to-one or one-to-many)
3. **Files and timing** — how are messages stored and scheduled? (Standard MIDI Files, tracks, events and timing values, tempo/BPM, time signature, used in DAWs, sequencers, and hardware)

**Common transports and connections:**
- **5-pin DIN** — classic MIDI connection used on many hardware devices
- **USB** — widely used on modern devices and computers
- **Bluetooth MIDI** — wireless MIDI connection for mobile devices and hardware
- **Network MIDI** — MIDI over local networks (Wi-Fi or Ethernet), e.g. RTP-MIDI, AppleMIDI
- **Virtual operating-system MIDI ports** — software MIDI connections inside one computer, e.g. IAC, loopMIDI
- **Application-to-application routing** — route MIDI between music applications

**Key idea:** MIDI is both a protocol and an ecosystem of devices, transports, and file formats.

### MIDI Messages: Protocol and Bytes
MIDI messages are **compact digital instructions**, not sound waveforms.

**Byte structure of a note-on message:**
| Status Byte | Meaning | Value |
|---|---|---|
| 144 | Note On + MIDI Channel 0 | 144 |
| 60 | Note Number (Pitch) | 60 |
| 80 | Velocity | 80 |

**How to read the example:**
```
Message type → Channel → Note number → Velocity → Raw bytes
note_on      → 0       → 60          → 80       → [144, 60, 80]
```

### Note Numbers, Pitch, and Velocity
**Frequency formula:**
```
frequency = 440.0 × 2^((note_number − 69) / 12)
```

**Useful pitch examples:**
| MIDI Note | Musical Note | Frequency |
|---|---|---|
| 60 | C4 (Middle C) | 261.63 Hz |
| 61 | C#4 / Db4 | 277.18 Hz |
| 62 | D4 | 293.66 Hz |
| 64 | E4 | 329.63 Hz |
| 67 | G4 | 392.00 Hz |
| 69 | A4 | 440.00 Hz |
| 72 | C5 | 523.25 Hz |

**Velocity → Amplitude (example):**
| Velocity | Amplitude |
|---|---|
| 0 | 0.00 |
| 64 | 0.50 |
| 80 | 0.63 |
| 127 | 1.00 |

Velocity influences playback, but the exact audible result depends on the synthesiser.

### Note State, Channels, and Controllers
**Handling note-on and note-off safely:**
A note may remain sounding if the application receives note-on but not note-off.
- Track active notes
- Support note-on with velocity zero as note termination
- Send all-notes-off / cleanup when closing

**Control-change messages:**
Controllers often use 0–127 and can be mapped to useful synthesis parameters. Example: filter cutoff = 200 + `controller_to_normalized(64) × 4800`.

### MIDI Files, Timing, and Delta Time
**Absolute time vs delta time:**
- Track events: note_on E4 (note 64) velocity = 80; note_off E4 (note 64) velocity = 0
- Absolute time (in beats): note_on at 2, note_off at 3
- Delta time (from previous event): note_on = 2, note_off = 1 (3 − 2)

**Live MIDI vs MIDI file:**
| Live MIDI | MIDI File |
|---|---|
| Timing comes from arrival | Timing is encoded |
| MIDI messages are processed in real time as they arrive from a device or software | Each event stores a delta time, and the player reconstructs the timeline during playback |

### MIDI in Practice
**Where MIDI is useful:**
- **Live performance** — trigger sounds, control parameters, synchronise equipment
- **Music production** — compose, record, control software and hardware instruments
- **Interactive installations** — use physical input to trigger sounds and visuals
- **Education and prototyping** — simple, widely supported format for learning and experimentation
- **Lighting / show control** — trigger and synchronise lights, stage effects, other systems
- **Games and multimedia** — control sound and interactive elements

**A MIDI file does not determine the final sound:**
The audible result depends on:
- The stored musical events
- Note timing and velocity
- Program and controller messages
- The receiving synthesiser
- Instrument patches or samples
- Mixing and effects
- Playback-device interpretation

**Key idea:** MIDI is powerful because it is flexible, but this also means the same file can sound different on different systems.

```python
from mido import Message

message = Message(

print(message)
print(message.bytes())
```

**Output (bytes):**

### 3.2 Multiple Message Types

```python
from mido import Message

messages = [
    Message("note_on", channel=0, note=60, velocity=80),
    Message("control_change", channel=0, control=7, value=100),
    Message("program_change", channel=0, program=0),
    Message("pitchwheel", channel=0, pitch=0),
    Message("note_off", channel=0, note=60, velocity=0),

for message in messages:
```

**Output (summary):**
| Message | Readable form | Bytes |
|---|---|---|
| note_on | note_on channel=0 note=60 velocity=80 time=0 | [144, 60, 80] |
| control_change | control_change channel=0 control=7 value=100 time=0 | [176, 7, 100] |
| program_change | program_change channel=0 program=0 time=0 | [192, 0] |
| pitchwheel | pitchwheel channel=0 pitch=0 time=0 | [224, 0, 64] |
| note_off | note_off channel=0 note=60 velocity=0 time=0 | [128, 60, 0] |

**Key points:**
- `Message(...)` constructs a MIDI message object.

### 3.3 Convert an Event Structure into Messages

```python
from mido import Message

NOTE_NUMBERS = {
    "C4": 60, "D4": 62, "E4": 64, "F4": 65,
    "G4": 67, "A4": 69, "B4": 71, "C5": 72,
}

def dynamic_to_velocity(dynamic):
    if not 0.0 <= dynamic <= 1.0:
        raise ValueError("Dynamic must be between 0 and 1.")
    return round(dynamic * 127)

def event_to_messages(event):
    note_number = NOTE_NUMBERS[event["pitch"]]
    velocity = dynamic_to_velocity(event["dynamic"])
    return (
        Message("note_on", note=note_number, velocity=velocity),
        Message("note_off", note=note_number, velocity=0),
    )
```

**Input event:**
```python
event = {
    "pitch": "C4",
    "onset_beats": 0.0,
    "duration_beats": 1.0,
    "dynamic": 0.8,
    "articulation": "normal"
}
```

**Output messages:**
```
note_on channel=0 note=60 velocity=102 time=0
note_off channel=0 note=60 velocity=0 time=0
```

**Key points:**
- `NOTE_NUMBERS` maps pitch names to MIDI note numbers.
- `dynamic_to_velocity()` converts a 0–1 dynamic value into a MIDI velocity from 0–127.
- `event_to_messages()` bridges symbolic musical events and actual MIDI messages.
- A single musical event typically needs both a `note_on` and a `note_off` message.

### 3.4 Note Number to Frequency

```python
def note_number_to_frequency(note_number):
    if not 0 <= note_number <= 127:
        raise ValueError(
            "MIDI note number must be between 0 and 127."
        )
    return 440.0 * 2 ** ((note_number - 69) / 12)
```

### 3.5 Velocity to Amplitude

```python
def velocity_to_amplitude(velocity):
    if not 0 <= velocity <= 127:
        raise ValueError(
            "Velocity must be between 0 and 127."
        )
    return velocity / 127.0
```

### 3.6 Handling Note-On and Note-Off Safely

```python
active_notes = set()

def handle_message(message):
    key = (message.channel, message.note)
    if (message.type == "note_on"
            and message.velocity > 0):
        active_notes.add(key)
    elif (message.type == "note_off"
          or (message.type == "note_on"
              and message.velocity == 0)):
        active_notes.discard(key)
```

### 3.7 Control-Change to Normalised Value

```python
def controller_to_normalized(value):
    if not 0 <= value <= 127:
        raise ValueError(
            "Controller value must be between 0 and 127."
        )
    return value / 127.0

filter_cutoff = (
    200
```

### 3.8 Creating a Short MIDI File

```python
from mido import (
    Message,
    MetaMessage,
    MidiFile,
    MidiTrack,
    bpm2tempo,
)

TICKS_PER_BEAT = 480
BPM = 100
midi_file = MidiFile(ticks_per_beat=TICKS_PER_BEAT)
track = MidiTrack()
midi_file.tracks.append(track)
track.append(MetaMessage("track_name", name="Programming Melody", time=0))
track.append(MetaMessage("set_tempo", tempo=bpm2tempo(BPM), time=0))
track.append(MetaMessage("program_change", program=0, channel=0, time=0))

melody = [(60, 1, 80), (62, 1, 80), (64, 1, 90), (67, 2, 90)]
for note_number, duration_beats, velocity in melody:
    track.append(MetaMessage("note_on", note=note_number, velocity=velocity, channel=0, time=0))
    duration_ticks = round(duration_beats * TICKS_PER_BEAT)
    track.append(MetaMessage("note_off", note=note_number, velocity=0, channel=0, time=duration_ticks))
midi_file.save("programming_melody.mid")
```

**How it works:**
1. **Create a MIDI file and a track** — `MidiFile(...)`, `MidiTrack()`
2. **Add tempo and program change** — set tempo (from BPM) and choose an instrument with `program_change`
3. **Add note_on and note_off messages** — each note is a `note_on` followed by a `note_off`, with duration in ticks
4. **Save the MIDI file** — `midi_file.save("programming_melody.mid")`

**Key ideas:**
- `ticks_per_beat` sets the timing resolution (ticks per quarter note). Here 480 ticks per beat.
- `bpm2tempo` converts BPM to MIDI tempo units (microseconds per beat), used in a `set_tempo` meta message.
- A note is created with a `note_on` followed by a `note_off` message. The `note_off` message's time is the duration in ticks.
- Each tuple in the melody is `(note_number, duration_beats, velocity)`. Duration in beats is converted to ticks using `duration_beats * TICKS_PER_BEAT`.

### 3.9 Inspecting a MIDI File

```python
from mido import MidiFile

midi_file = MidiFile("programming_melody.mid")
print("Ticks per beat:", midi_file.ticks_per_beat)
for track_number, track in enumerate(midi_file.tracks):
    print(f"\nTrack {track_number}: {track.name}")
    absolute_ticks = 0
    for message in track:
        absolute_ticks += message.time
        print(f"{absolute_ticks:5d} ticks | {message}")
```

**Output (example):**
```
Ticks per beat: 480

Track 0: Programming Melody
    0 ticks | MetaMessage('track_name', name='Programming Melody', time=0)
    0 ticks | MetaMessage('set_tempo', tempo=600000, time=0)
    0 ticks | program_change channel=0 program=0 time=0
    0 ticks | note_on channel=0 note=60 velocity=80 time=0
  480 ticks | note_off channel=0 note=60 velocity=0 time=480
  480 ticks | note_on channel=0 note=62 velocity=60 time=0
  960 ticks | note_off channel=0 note=62 velocity=0 time=480
```

**How it works:**
1. **Load the MIDI file** — create a `MidiFile` object from the file.
2. **Read the timing resolution** — print `ticks_per_beat`.
3. **Loop through tracks** — use `enumerate()` to get each track's index and name.
4. **Accumulate delta times** — each message's `time` is a delta time. Add it to `absolute_ticks` to get the absolute tick position.

### 3.12 Sending a Note Safely

```python
import time
import mido

def play_note(
    output_port,
    note_number,
    velocity=80,
    duration_seconds=0.5,
    channel=0
):
    note_on = mido.Message(
        "note_on",
        note=note_number,
        velocity=velocity,
        channel=channel
    )
    note_off = mido.Message(
        "note_off",
        note=note_number,
        velocity=0,
        channel=channel
    )

    output_port.send(note_on)  # send note_on message

    try:
        time.sleep(duration_seconds)  # keep the note on
    finally:
        output_port.send(note_off)  # ensure note_off is sent

output_names = mido.get_output_names()  # list available MIDI outputs

if output_names:
    with mido.open_output(output_names[0]) as output_port:
        play_note(output_port, note_number=60)  # play Middle C (C4)
```

**Function parameters:**
| Parameter | Type | Description | Default |
|---|---|---|---|
| `output_port` | mido port | MIDI output port to send messages | (required) |
| `note_number` | int | MIDI note number (0–127) | (required) |
| `velocity` | int | How loud the note is (0–127) | 80 |
| `duration_seconds` | float | How long to keep the note on (in seconds) | 0.5 |
| `channel` | int | MIDI channel (0–15) | 0 |

**What happens:**
```
Python program (mido) → note_on → wait → note_off → MIDI device or software synthesizer → You hear a note
```

**Key point:** Always send a `note_off` message (e.g. using a `finally` block) to avoid stuck notes, especially if an error occurs.
